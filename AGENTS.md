# Syndicate AI — Agent Guidelines & Engineering Standards

These rules are non-negotiable for all AI coding agents working in this repository.

---

## 1. Zero Hardcoded Theme Values & Zero Hardcoded UI Text

### A. Strict Design Token Enforcement (Theme, Spacing, Typography)
* **NEVER hardcode raw hex codes, RGB, HSL, or magic pixel values** (e.g. `bg-[#0f141f]`, `text-[#f0b90b]`, `p-[14px]`, `text-[13px]`) in component files or inline styles.
* **ALWAYS use the design token variables** configured in `src/app/globals.css`:
  * **Theme Colors (15 tokens):** `var(--theme-bg-base)`, `var(--theme-bg-surface)`, `var(--theme-bg-elevated)`, `var(--theme-bg-overlay)`, `var(--theme-border-subtle)`, `var(--theme-border-strong)`, `var(--theme-text-primary)`, `var(--theme-text-secondary)`, `var(--theme-text-muted)`, `var(--theme-brand-binance)`, `var(--theme-brand-accent)`, `var(--theme-status-success)`, `var(--theme-status-danger)`, `var(--theme-status-warning)`, `var(--theme-status-info)`.
  * **Text Sizes (8 tokens):** `var(--text-2xs)`, `var(--text-xs)`, `var(--text-sm)`, `var(--text-base)`, `var(--text-lg)`, `var(--text-xl)`, `var(--text-2xl)`, `var(--text-3xl)`.
  * **Font Weights (5 tokens):** `var(--weight-regular)`, `var(--weight-medium)`, `var(--weight-semibold)`, `var(--weight-bold)`, `var(--weight-extrabold)`.
  * **Line Heights (5 tokens):** `var(--leading-none)`, `var(--leading-tight)`, `var(--leading-snug)`, `var(--leading-normal)`, `var(--leading-relaxed)`.
  * **Spacing (5 tokens):** `var(--spacing-xs)`, `var(--spacing-sm)`, `var(--spacing-md)`, `var(--spacing-lg)`, `var(--spacing-xl)`.
* Utilize the corresponding Tailwind utility classes generated by `@theme` (e.g., `bg-theme-bg-surface`, `text-theme-brand-binance`, `text-xs`, `font-semibold`, `p-spacing-md`, `border-theme-border-subtle`).

### B. Structured UI Copy & Text Constants
* **NEVER scatter arbitrary hardcoded copy strings** across JSX components.
* Place user-facing labels, headings, modal text, button strings, tooltips, error messages, and descriptions inside dedicated, organized constants/dictionaries (e.g., `src/constants/content.ts` or scoped module configuration files).

## 2. Runtime & Package Management: We Use Bun Around Here

* **Bun is the exclusive package manager and JavaScript runtime** across this entire project (`bun@1.4.0+`).
* **NEVER execute, propose, or document** `npm`, `pnpm`, `yarn`, or `npx`.
* Use Bun CLI equivalents exclusively:
  * Package installation: `bun add <pkg>`, `bun add -d <pkg>`
  * Package removal: `bun remove <pkg>`
  * Running scripts: `bun run dev`, `bun run build`, `bun run lint`
  * Executing binaries: `bun x <tool>` (e.g., `bun x oxlint`, `bun x tsc`)

---

## 3. Tooling Standards: TS7 & Oxlint

* **TypeScript 7 (TS7):** All code must strictly type-check with the native Go TypeScript compiler (`typescript@7.0.2+`). Run checks via `bun x tsc --noEmit`. No `any` escapes without documented justification.
* **Oxlint:** Oxlint is the sole linter in this repository (`oxlint@1.81.0+`). Do not install or introduce ESLint. Run linting via `bun run lint`. Ensure zero warnings and zero errors before completing tasks.
* **Next.js 16:** Always use modern Next.js 16 conventions (Turbopack, async route `params`, typed layouts, React 19).

---

## 4. Clear Separation of Concerns & Modular Architecture

Every component and module must have one single, clearly defined responsibility:

```
src/
├── app/                  # Route boundaries, page orchestrations, layouts
├── components/           # Presentation UI components (stateless where possible)
│   ├── cockpit/          # Visual cockpit elements (trading view chart, strategy cards)
│   ├── stream/           # Multi-agent visual conversation stream
│   └── common/           # Reusable UI primitives (buttons, badges, indicators)
├── constants/            # Centralized UI text, dictionary copies, default configs
├── lib/
│   ├── agents/           # Autonomous agent logic (Analyst, Risk Arbiter, Executor)
│   ├── binance-mcp/      # Binance Agent OS MCP clients & mock simulation adapters
│   ├── risk-engine/      # Deterministic mathematical risk calculation functions
│   ├── x402/             # Machine-to-machine HTTP 402 challenge-response settlement
│   ├── types/            # Domain TypeScript interfaces and Zod validation schemas
│   └── utils.ts          # Pure helper utilities
```

* **Data & Validation Layer:** All network inputs, agent messages, MCP payloads, and x402 receipts must be validated at runtime via **Zod schemas**.
* **Risk Engine:** Mathematical risk evaluations (slippage against order book depth, drawdown percentage, position sizing caps) must be **pure, deterministic TypeScript functions**, entirely decoupled from LLM prompting.
* **UI Components:** Responsible strictly for visual rendering and user interaction; delegate agent orchestration and business workflows to dedicated controller modules or hooks.

---

## 5. Clean, Organized, and Well-Commented Code

* **Self-Documenting & Descriptive:** Use explicit, intention-revealing names for variables, functions, and interfaces. Avoid obscure abbreviations.
* **TSDoc / JSDoc on Non-Obvious Logic:** Add structured comments to all financial calculations, slippage formulas, cryptographic certificate generation, and agent workflow orchestrations.
* **Preserve Integrity:** Never introduce dead code, commented-out experiments, or unused imports. Keep codebase lean and production-grade.
